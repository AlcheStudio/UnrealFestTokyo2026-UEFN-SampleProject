# MCP で UEFN を操作する

この会場は、Verse のコードもレベルへの配置も、ほとんどを AI が **MCP** 経由で行いました。ここでは、MCP で何ができて何ができないか、そのためにどんな作り方をしているかを説明します。

## MCP とは

MCP（Model Context Protocol）は、AI がアプリケーションを操作するための共通の口です。UEFN には MCP サーバーが組み込まれていて、AI から次のことができます。

- Verse のファイルを読む・書く・ビルドする
- レベルの entity を作る・動かす・親子にする、component を付ける・外す、`@editable` の値を変える
- デバイスを置く
- マテリアル、メッシュ、Niagara、ウィジェットなどのアセットを作る・変える
- ログや、セッション中の Verse の出力（Print）を読む
- ビューポートの画像を撮って、配置を確かめる

## つなぎ方

1. UEFN 側で MCP サーバーを有効にします（プロジェクト設定の AI / MCP の項目）。
2. MCP に対応した AI クライアントに、UEFN の MCP サーバーを登録します。
3. AI に「MCP の接続を確認して」と頼むと、使えるツールの一覧が返ってきます。

## この会場で AI が実際にやったこと

| やったこと | 使った機能 |
|---|---|
| 26 個の System の Verse を書き、ビルドが通るまで直す | Verse の書き込み・置換・`BuildAll` |
| ホログラムのマテリアル、ボリューム用メッシュ、レーザーの Niagara を作る | マテリアル / メッシュ / Niagara のツール |
| 展示を 5×5 のエリアに並べ直し、床と看板を置く | entity の作成・移動・親子付け |
| 各展示に共通の検知部品を付け、値を揃える | component の追加・プロパティの書き込み |
| セッションの Print を読んで、動かない原因を探す | Verse 出力の読み取り |
| 上から見た画像で配置を確かめる | ビューポートの撮影 |

## MCP で触りやすいように、会場が守っている作り方

MCP は「部品を 1 つ付ける」「値を 1 つ書く」が得意で、「配列の 3 番目を書き換える」「選択肢から選ぶ」は苦手です。そのため、この会場の Verse は次のルールで書いてあります。

- **配列を `@editable` にしない**。順番が要るときは、子 entity に `Order` の数字を持たせます。
- **選択肢（enum）を `@editable` にしない**。種類の違いは「どの部品を付けるか」で表します。
- **entity どうしは参照を持たせない**。「あの entity」を指す代わりに、同じ entity の部品を探す、親へ知らせる、タグで探す、のどれかにします。デバイス（NPC スポナーなど）への参照だけは `@editable` で持ち、人がエディターで割り当てます。
- 部品の先頭に「役割 / 置き方 / 同じ entity / 親 / 子」を書く。AI も人も、置き方をコードから読めます。

## できないこと・気をつけること

| できない / 注意 | 会場での対処 |
|---|---|
| プレハブの中身を編集したあと、置いたものに反映する | プレハブの作成・置換は MCP でできる（この会場の 55 個の展示は MCP でプレハブ化した）。中身を変えたら「反映」の操作が別に要る |
| component の `@editable` にデバイスへの参照を入れる | 人がエディターで割り当てる（会場の NPC スポナーの参照はこれ） |
| セッションの開始 | 重い処理なので人が開始し、AI は出力を読む |
| ビルドが通らない状態でレベルを保存する | entity から Verse の部品が消えることがある。必ずビルドが通ってから保存する |
| 名前が変わる部品をビルドする | 先にレベルから外す。古い名前の部品が置かれたままだと保存で壊れる |

## AI に頼むときのコツ

- 「何をどこに置くか」より「どう動いてほしいか」を伝える。配置と部品の選び方は AI が決められます。
- 動かないときは「Print を読んで」と頼む。セッションの出力は MCP から読めます。
- 大きく変えるときは、先に「レビューだけ」と頼むと、変更の前に設計の問題を指摘してもらえます。
